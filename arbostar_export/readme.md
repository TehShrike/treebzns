# arbostar_export/

Exported data pulled out of the client's ArboStar account (a tree-service CRM). Generated by
the scripts in [`../scripts/arbostar/`](../scripts/arbostar/readme.md) — **see that readme for
the full story**: how the endpoints work, the status-filter gotchas, the datatable-vs-full-entity
column gaps, and the credential setup (`.arbostar_session.json`).

## What's in here

Two files per dataset:

- **`<name>.js`** — the data. An ESM module: `export default [ ...records ]`. **Gitignored**
  (`*.js` in this dir) because it's client PII. Regenerate with the export scripts.
- **`<name>.d.ts`** — committed. Types the matching `.js`: it exports the record type (e.g.
  `ArbostarClient`) and declares the default export as an array of it. So
  `import clients from '#arbostar_export/clients.js'` is typed `ArbostarClient[]`.

Consume via the `#arbostar_export/*` import map (defined in package.json / tsconfig):

```ts
import clients from '#arbostar_export/clients.js'            // ArbostarClient[]  (data — must exist locally)
import type { ArbostarClient } from '#arbostar_export/clients.d.ts' // the record type only
```

## Regenerating

Run the scripts in `../scripts/arbostar/` (each needs a valid `.arbostar_session.json` there —
a stale session fails with `request failed: 302`). `export_all.ts` runs them all, in parallel
where dependencies allow:

```sh
node ../scripts/arbostar/export_all.ts
```

Or run them individually — some read earlier outputs, so mind the order:

```sh
node ../scripts/arbostar/export_clients.ts      # clients.js (raw rows, contacts nested)
node ../scripts/arbostar/export_leads.ts        # leads.js
node ../scripts/arbostar/export_estimates.ts    # estimates.js
node ../scripts/arbostar/export_invoices.ts     # invoices.js
node ../scripts/arbostar/export_workorders.ts   # workorders.js
node ../scripts/arbostar/export_line_items.ts   # line_items.js  (reads estimates.js; slowest — ~355 KB/estimate)
node ../scripts/arbostar/export_payments.ts     # payments.js
node ../scripts/arbostar/export_users.ts        # users.js
node ../scripts/arbostar/export_declines.ts     # declines.js  (run alongside export_estimates.ts so the two agree)
node ../scripts/arbostar/export_work_types.ts   # crew_roles.js + work_types.js  (reads estimates.js)
node ../scripts/arbostar/export_tree_inventory.ts # tree_inventory.js + tree_inventory_sets.js  (walks the global tis_id sequence)
```

If you add/remove fields in an export script's mapper, update the matching `.d.ts` here so it
keeps describing the `.js` accurately.

## Gotchas worth remembering (full detail in the scripts readme)

- **Line items are the universal source** for estimate/invoice/work-order lines: each row carries
  `estimate_id` + `invoice_id`, because ArboStar has no JSON line-item endpoint for invoices or
  work orders. Filter `line_items.js` by `invoice_id` for an invoice's lines.
- **These are curated subsets.** The datatable endpoints omit most raw columns, and even the full
  entity endpoints hold ~2-8× more fields than exported here. The scripts readme has per-entity
  tables of exactly what's missing if you need more.
- **Leads/invoices need every status** to be complete (the "All" tab hides most rows); that logic
  lives in the fetcher, but it's why counts here are much larger than the app's default views.
