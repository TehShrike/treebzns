# 0041 plan: clock sessions

Schema for clocking employees into projects. Not yet a migration. Sessions feed real project cost and time-spent reporting. They are not used for payroll.

Decisions so far:

- Only `supersedes_clock_session_id` links session generations. The mirrored `superseded_by` column is gone.
- No `project_crew_id`. project_crew is the schedule ("this crew's timeline involves these projects"). clock_session is what a group of people actually worked on at a time. Different meanings, no link. `crew_id` stays as a direct optional reference.
- `scripts/export_schema.ts` now excludes VIRTUAL/STORED GENERATED columns from insertable types (done, in this change).
- clock_session_employee keeps a plain index on clock_session_id instead of the old three-column unique key. The company/clock_in index is dropped. See the index notes.
- clock_session_employee has `clock_in_day`, a company-local date the app derives from clock_in. The per-employee index is `(employee_id, clock_in_day)`, smaller than indexing the datetime.
- No `action` column on history. Old/new clock values say everything.
- All current companies get `America/Chicago`. The column has no default, so new companies must set a timezone at creation.
- time_entry is dropped in this migration with no data migration. No app code references it. Its schema/type files are autogenerated and clean themselves up on export.

## Proposed schema

Conventions follow current_schema.sql: int unsigned surrogate keys, company_id on every table, no declared FOREIGN KEYs, utf8mb4_general_ci, utc_timestamp() defaults.

### company timezone

Required for correct work_date derivation. All datetimes are UTC and company has no timezone today. The DEFAULT in the ADD backfills every existing company to America/Chicago. The DROP DEFAULT then forces new companies to set a timezone explicitly.

```sql
ALTER TABLE `company`
  ADD COLUMN `timezone` varchar(64) COLLATE utf8mb4_general_ci NOT NULL DEFAULT 'America/Chicago';

ALTER TABLE `company`
  ALTER COLUMN `timezone` DROP DEFAULT;
```

### clock_session

A session is an immutable declaration of work: one project, a fixed set of line items. Changing the line item set closes this session and opens a successor. created_at is the informational start. The session has no authoritative span of its own. Derive the span from min(clock_in) and max(clock_out) of its members.

```sql
CREATE TABLE `clock_session` (
  `clock_session_id` int unsigned NOT NULL AUTO_INCREMENT,
  `company_id` int unsigned NOT NULL,
  `project_id` int unsigned NOT NULL,
  `crew_id` int unsigned DEFAULT NULL,
  `work_date` date NOT NULL,
  `supersedes_clock_session_id` int unsigned DEFAULT NULL,
  `notes` varchar(500) COLLATE utf8mb4_general_ci NOT NULL DEFAULT '',
  `opened_by_employee_id` int unsigned NOT NULL,
  `created_at` datetime NOT NULL DEFAULT (utc_timestamp()),
  `updated_at` datetime NOT NULL DEFAULT (utc_timestamp()),
  PRIMARY KEY (`clock_session_id`),
  UNIQUE KEY `uq_clock_session_supersedes` (`supersedes_clock_session_id`),
  KEY `idx_clock_session_company_work_date` (`company_id`,`work_date`),
  KEY `idx_clock_session_project` (`project_id`),
  KEY `idx_clock_session_crew` (`crew_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci;
```

`uq_clock_session_supersedes` limits each session to one successor. It also indexes the "find the successor" lookup. MySQL allows many NULLs in a unique key, so root sessions are fine.

### clock_session_line_item

The line items this session covers. Insert-once. Never mutated.

```sql
CREATE TABLE `clock_session_line_item` (
  `clock_session_line_item_id` int unsigned NOT NULL AUTO_INCREMENT,
  `company_id` int unsigned NOT NULL,
  `clock_session_id` int unsigned NOT NULL,
  `project_line_item_id` int unsigned NOT NULL,
  `created_at` datetime NOT NULL DEFAULT (utc_timestamp()),
  PRIMARY KEY (`clock_session_line_item_id`),
  UNIQUE KEY `uq_csli_session_line_item` (`clock_session_id`,`project_line_item_id`),
  KEY `idx_csli_project_line_item` (`project_line_item_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci;
```

### clock_session_employee

Where all actual time lives. One row per person per stint in a session. clock_in is always populated. The app defaults founding members to the session's created_at. clock_out NULL means still on the clock.

The app sets clock_in_day from clock_in in the company's timezone, the same derivation as clock_session.work_date. It is not a generated column on purpose. A SQL expression over clock_in would give the UTC day, not the company-local day. An edit to clock_in must update clock_in_day with it.

```sql
CREATE TABLE `clock_session_employee` (
  `clock_session_employee_id` int unsigned NOT NULL AUTO_INCREMENT,
  `company_id` int unsigned NOT NULL,
  `clock_session_id` int unsigned NOT NULL,
  `employee_id` int unsigned NOT NULL,
  `clock_in` datetime NOT NULL,
  `clock_in_day` date NOT NULL,
  `clock_out` datetime DEFAULT NULL,
  `clocked_in_by_employee_id` int unsigned NOT NULL,
  `clocked_out_by_employee_id` int unsigned DEFAULT NULL,
  `open_employee_id` int unsigned GENERATED ALWAYS AS
    (if(`clock_out` is null,`employee_id`,NULL)) VIRTUAL,
  `created_at` datetime NOT NULL DEFAULT (utc_timestamp()),
  `updated_at` datetime NOT NULL DEFAULT (utc_timestamp()),
  PRIMARY KEY (`clock_session_employee_id`),
  UNIQUE KEY `uq_cse_open_employee` (`open_employee_id`),
  KEY `idx_cse_session` (`clock_session_id`),
  KEY `idx_cse_employee_clock_in_day` (`employee_id`,`clock_in_day`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci;
```

`uq_cse_open_employee` enforces at most one open stint per employee anywhere.

Index reasoning:

- `idx_cse_session` is the main read path: load a session's stints. The old unique key `(clock_session_id, employee_id, clock_in)` covered this lookup but its uniqueness was hollow. It only blocked two stints with an identical clock_in. The real invariant, no overlapping stints per employee, cannot be expressed by an index. A plain index on clock_session_id is enough.
- `idx_cse_employee_clock_in_day` serves per-employee time queries: an employee's stints in a date range, and "what did this employee work on recently". A date entry is 3 bytes against 5 for a datetime, so the index stays small, and range queries phrase naturally as day bounds.
- No company/clock_in index. Company-wide reports can go through clock_session via `idx_clock_session_company_work_date`, then join stints through `idx_cse_session`. Add a direct index later if a query needs it.
- `idx_clock_session_crew` is a bare crew_id index until more specific index needs surface. crew_id is a globally-unique id, so no company_id prefix.

### clock_session_employee_history

Audit trail. Time feeds real project cost, so edits need history. One row per edit. A delete, if ever allowed, is a row with previous values and NULL new values. new_clock_in NULL is unambiguous because clock_in is NOT NULL on the live row.

```sql
CREATE TABLE `clock_session_employee_history` (
  `clock_session_employee_history_id` int unsigned NOT NULL AUTO_INCREMENT,
  `company_id` int unsigned NOT NULL,
  `clock_session_employee_id` int unsigned NOT NULL,
  `previous_clock_in` datetime DEFAULT NULL,
  `previous_clock_out` datetime DEFAULT NULL,
  `new_clock_in` datetime DEFAULT NULL,
  `new_clock_out` datetime DEFAULT NULL,
  `changed_by_employee_id` int unsigned DEFAULT NULL,
  `created_at` datetime NOT NULL DEFAULT (utc_timestamp()),
  PRIMARY KEY (`clock_session_employee_history_id`),
  KEY `idx_cseh_clock_session_employee` (`clock_session_employee_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci;
```

### time_entry

Discarded with no data migration. No app code references it.

```sql
DROP TABLE `time_entry`;
```

## Open notes and concerns

### App behavior to pin down

1. **No `clock_out >= clock_in` enforcement in the schema.** The schema uses no CHECK constraints. Enforce this with a runtime assert in the module that writes stints. Test the throw. The same module asserts that clock_in_day equals clock_in in the company's timezone, on insert and on every clock_in edit.

2. **Supersede handoff ordering.** In one transaction: close the open stints in the old session first, then insert the open stints in the successor. `uq_cse_open_employee` is checked per statement, so the reverse order fails.

3. **History coverage.** History records clock_in and clock_out changes only. It cannot record a stint moving to another session or employee. Assert that those columns never change on update. Test the throw.

4. **Timezone handling.** Company creation must now supply a timezone, since the column has no default. The regenerated `DbInsertableCompany` type makes this a compile error in `create_company.ts` callers until they do. Validate names against `Intl.supportedValuesOf('timeZone')`. Derive work_date in the app. SQL-side CONVERT_TZ needs the MySQL timezone tables loaded, so avoid it.

5. **`open_employee_id` may be removed later.** If the one-open-stint rule moves to the app, drop the generated column and its unique key together.
