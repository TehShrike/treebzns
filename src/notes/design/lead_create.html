Design notes

  • One search box, four sections, top to bottom. The person on the phone reads down the page in the order the conversation goes.
  • Picking a client fills the client, address, and contact sections. A new client starts with empty fields and the same sections. There is no separate "new client" screen.
  • The contact section exists because the contact is baked onto the project. It starts as a copy of the client's phone and email, and it can differ.
  • The status dropdown holds only the two lead documents. Everything else moves through the project screen.
  • Availability windows are collected here, while the client is on the phone. The estimator sees them on the estimating screen and the scheduler sees them on the board.
  • No map details in the first version. The screen collects only the typed address. Geocoding into project.latitude / longitude comes later, and the columns are nullable, so a lead saves without them.
  • Lead source is a BetterDataList over the free text column (project.lead_source). The options are the distinct values already saved, and any new text is accepted. That keeps entries consistent for the reporting in src/notes/big_todos.md. The data can move to its own table later if needed.
  • client.primary_client_address_id is not nullable, and that is intentional. The saved-address dropdown has an "Add a new address" option, the default for a new client. Saving requires an address record, though its fields can all be empty.
