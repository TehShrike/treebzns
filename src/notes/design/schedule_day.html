Design notes

  • This screen exists because the map is only useful in the context of one crew. Zoomed out to every crew, the pins are noise. Zoomed in to one crew's route, a hollow pin near the route is an obvious pickup.
  • Each card is one project_crew row. A card is either ordered or pinned, never both. An ordered card shows "2nd stop" (day_order). A pinned card shows a clock time (start_time) and a blue left edge.
  • The queue holds projects whose document says should_be_worked, that are open, and that have no visit on this day or later. With a route on the map, "closest to the route first" beats "oldest first" as the default sort.
  • Workers are read-only here. The week overview assigns them. One screen, one job.
  • Estimating works the same way: pick the Estimating crew in the dropdown, and the queue shows leads with estimate_availability windows instead of approved work.
  • Open: a 16 hour job needs more than one day. project_crew allows one row per project, crew, and date, so a multi-day job is several rows. Does the card need to show "day 1 of 2"?
  • Open: which line items get worked on a visit (project_crew_project_line_item) is set somewhere. Right now the card only lists them. Set it in a panel that opens from the card?
  • Open: drive time. "Off route" miles need a distance from the pin to the nearest leg of the route. A first version can use straight-line distance.
