treebzns screen designs

Static mockups. No JavaScript, no data.

Each page draws one screen from src/notes/screens_needed.md, with the columns from schema/current_schema.sql that feed it. The pages load the real app CSS, so the controls look like the app. Every page ends with design notes and open questions.

Turn on "Show column names" on any page to see the table and column behind each control.

Office screens

  • Create a lead — one search box for the client, then the fields the first phone call collects.
  • Project list — report view with money, dates, and age.
  • Client — details, addresses, projects, billing.
  • Project — the internal project screen with the document path.
  • Job scheduling (week overview) — every crew's week, and worker assignment.
  • Crew day scheduling — one crew, one day, a queue, and a zoomed map.
  • Crews — crew rosters and work skills.
  • Settings — users, roles, work skills, line item templates.

Field screens

  • My jobs (crew and foreman) — today's work, phone numbers, clock in and out.
  • Estimating — photo and note dump, then line items.

Customer screens

  • Proposal — the customer declines optional work and approves.
  • Work order — approved work and a guess at the visit date.
  • Closed work order (invoice) — locked amount, with a switch back to the full detail view.

Read this first

  • Three of these screens already exist in some form: create a lead, project list, and client. The mockups show what the design doc asks for, which is more than the code does today.
  • 98.css sets h1 to 5rem and h2 to 2.5rem. The app screens use h1 today, so they render at 5rem. These mockups override the heading sizes. The app needs the same decision.
  • Photos are drawn as gray boxes. Image markup is a separate project (see src/notes/big_todos.md).
