Design notes

  • The screen runs in the order the work happens: read what the office collected, dump everything, then cut the dump into line items. Nothing forces the estimator to make a line item before they walk the yard.
  • "Make a line item from the selection" is the key move. The estimator types or speaks one long note, then selects a paragraph at a time. The selected text becomes work_details and the estimator writes a short title.
  • Photos land on the project first. Dragging a photo onto a line item writes the project_line_item_image row. A photo that never gets dragged still shows on the project.
  • A template fills the title, hours, price, and the default work skills. Every field stays editable, and the line item keeps line_item_template_id for reporting.
  • The blended rate line is help text, not a rule. It multiplies the average work_skill.hourly_rate for the item's skills by the hours. The estimator still types the price.
  • Open: "Send the proposal" moves the document from Lead (Qualified) to Proposal. Does it also send the email, or is sending a second action?
  • Open: photo markup is not built. This screen only has a button for it.
  • Open: project_line_item.estimated_hours is an unsigned int, so half hours do not fit. Estimators think in half days. Change the column, or count in quarter hours?
  • Open: the design doc says a separate add-on tier is deferred. This screen has one "customer can decline" flag per line item, which matches client_optional today.
