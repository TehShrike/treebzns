Design notes

  • The board holds one day. Each crew column is one crew row, and each card is one project_crew row.
  • A card is either ordered or pinned, never both. An ordered card shows "2nd stop" (day_order). A pinned card shows a clock time (start_time) and a blue left edge. Dragging a card between the two changes which column gets a value.
  • The queue holds projects whose document says should_be_worked, that are open, and that have no visit on this day or later. The default order is emergencies first, then the date the client approved the work.
  • Skills are checked, not enforced. The warning panel compares the skills the day's line items need against the skills the assigned people hold. Andrew can still schedule the job.
  • Estimating is a crew column like any other. An estimator is one person on a crew, and the visit is still a project_crew row.
  • Open: crew capacity. "11 of 10 hours booked" needs a hours-per-day number per crew. Nothing in the schema holds it. Add crew.hours_per_day, or drop the warning?
  • Open: a 16 hour job needs more than one day. project_crew allows one row per project, crew, and date, so a multi-day job is several rows. Does the card need to show "day 1 of 2"?
  • Open: which line items get worked on a visit (project_crew_project_line_item) is set somewhere. Right now the card only lists them. Set it in a panel that opens from the card?
  • Open: drive time. The map orders pins, but nothing computes distance. A first version can show straight-line miles from the shop.
