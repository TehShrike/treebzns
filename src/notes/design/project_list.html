Design notes

  • Two ages, not one. "Age" is how old the project is. "In this status" is how long it has sat in the current document. A proposal that has sat 39 days is the one to call about, and the second column is the only one that shows it.
  • Red marks the two things that need action: a work order with no visit, and a proposal that has sat too long.
  • The summary bar sits above the table and follows the filters. It is the answer to "how much work is on the books", which the doc calls a report question.
  • The same table, filtered to one client, is the Projects tab on the client screen.
  • The search box takes a name, a phone number, an address, or a project number. It is the same behavior as the client search on the create-a-lead screen.
  • Open: "not scheduled" and "next visit" need a join to project_crew. For a closed project the useful date is the last visit, not the next one.
  • Open: balance needs invoices and payments per project. A project with no invoice shows a dash. Is total or balance the number people want in this table?
  • Open: how long should a saved view live? "Save this view" implies storage. A URL with the filters in it may be enough, and the current screen already puts filters in the route.
  • Open: expired proposals. If expiration means "hide from reports after this many days", this table needs a switch to show them again.
